# Dance Pulse

Telegram-бот для танцевальных школ. Делает две вещи, которых нет в коробочных CRM:

1. **Опрос посещаемости** — перед каждым занятием спрашивает учеников «придёшь?» и даёт преподавателю готовую сводку.
2. **Автосбор саппортов** (киллер-фича) — ловит гендерный перекос в парах лид/фолловер и сам добирает помощников из пула.

Это **не CRM**. Учёт абонементов, платежей, расписания залов — у школ для этого уже есть коробочные продукты (AppEvent, Impulse CRM и т.п.). Бот сознательно делает только то, чего эти CRM не делают.

## Что работает

**Преподаватель** — нижнее меню: `🏫 Школа · 👥 Мои группы · 📅 Сегодня · 📊 Статистика · 🆘 Саппорты · ❓`. Команды `/start`, `/today`, `/stats`, `/pool`, `/help` тоже работают.

- **Школа** (`/school`) — все группы школы (📋), создание группы (➕ Новая группа, owner), приглашение co-admin'а одноразовой ссылкой с TTL, часовой пояс, переименование/удаление/выход. Настроек автодобора тут больше нет — они личные, в `/pool`.
- **Мои группы** (`👥 Мои группы`) — только группы, где ты ответственный. Все группы школы — через карточку школы (видимость не ограничена, это фокус-фильтр).
- **Создание группы** — мастер на aiogram-dialog (направление → уровень → дни → время → площадка → зал → ведущие), «◀ Назад» на каждом шаге; в конце картинка QR + ссылка. Автор группы автоматически становится её ответственным и куратором добора.
- **Карточка группы** — «👥 Ученики», «📨 Пригласить», «📢 Сообщение», «✏️ Изменить», «👤 Ответственные», «🚫 Отменить занятие», «✏️ Отметить посещаемость», «⏸ Пауза», «🗑 Удалить» (мёртвые скрываются).
- **Ответственные за группу** (owner → «👤 Ответственные») — кому идут уведомления группы (сводки, пинги) и что попадает в его «Мои группы». Picker автодобора идёт **куратору** (lead) группы. Не назначено — fallback на всех членов школы.
- **Карточка ученика** — тап по имени: пол, уровень в **твоём** пуле, группы. Переключить уровень в твоём пуле / пол, убрать из группы или (walk-in) записать постоянно. Toggle идемпотентны.
- **Опросы посещаемости** — за `lead_hours` бот шлёт «придёшь?»; карточка показывает **«кто уже идёт»** (соц-доказательство, разбивка М/Ж) и **дедлайн ответа** «до HH:MM»; `/today` — сводка с переключателем день/неделя и пингом молчащим; на середине окна — авто-сводка ответственным.
- **Auto-reminder** — за 4 ч и 1 ч молчащим «⏰ Напоминаю» (идемпотентно), в **commitment-тоне** («без тебя пара останется без партнёра»).
- **Реактивация молчунов** — пропустил последние 2 занятия подряд → мягкий персональный пинг «скучаем, придёшь?» (throttle: не чаще раза в 14 дней).
- **Broadcast в группу** — preview-confirm перед рассылкой.
- **Post-lesson отметка** — ростер с toggle (☐→✅→❌→☐) + walk-in; приглашённые саппорты отдельной секцией 🆘 (их явка двигает «помог N раз»). По 10.
- **`/stats`** — «обещали M → пришли N (no-show: K)», средний отклик и реальная посещаемость; переключатель **«вся школа ↔ только мои группы»** и кнопка **📤 Экспорт CSV** прямо в экране.

**Ученик** — всё кнопками: онбординг по QR/ссылке (имя + пол), ответ на опрос одной кнопкой (flip — другой).

**Автосбор саппортов** — двухфазный, у каждого препода **свой пул и свои настройки**; добор группы ведёт её **куратор** (lead):

- **Фаза 1 — вечерний разбор.** Накануне в личное время куратора (default 20:00 по TZ школы) бот считает баланс по полу среди «приду». Перекос ≥ порога (default 2) → запускается добор по выбранному **режиму** (см. ниже).
- **Фаза 2 — добор остатка.** За несколько часов (default 3 ч, можно выкл) — пересчёт с учётом согласившихся; новая дыра от отмен → дособор.
- **Режимы добора (B16, личные у препода, кнопками в `/pool`):**
  - 🙋 **Сам выбираю** (`curated`, дефолт) — куратору сводка + picker **его** пула, «Позвать» вручную.
  - 🏁 **Открытая гонка** (`open_race`) — приглашения сразу всему подходящему пулу (свой + коллеги), кто первый откликнулся.
  - 🎯 **Авто топ-N** (`auto_top`) — бот сам зовёт top-N по уровню пула (N = дефицит).
  - ⏱ **Авто-фолбэк** (`escalate`) — как curated, но если куратор не разобрал за 6 ч до занятия — бот авто-докидывает (open-race).
- **Двухуровневый picker** — сначала пул куратора; кнопка «➕ из пула коллег» дораскрывает саппов из пулов других преподов школы; кнопка «✗ Не сейчас · баланс ок» закрывает добор на это занятие без пинга (graceful-выход).
- **Живой баланс-бар** — баланс пар в recruit-сообщении куратора обновляется в реальном времени при отклике/отказе саппорта.
- Первые N согласившихся занимают места. Поздний тап после начала занятия не засчитывается. «помог N раз» — по факту явки (отметка в пост-leson ростере), не по отклику.
- Нудж «добор не разобран» если куратор молчит близко к занятию; «никто не откликнулся» если приглашённые молчат час.
- **`/pool` (🆘 Саппорты)** — личный пул препода: тап по человеку 1→2→3→убрать; **📨 Пригласить саппорта** (персональная ссылка `start=support_…` — человек заводится без группы и сразу в твой пул); **⚙ Настройки добора** (режим · порог · время разбора · добор остатка — личные).

Фидбек-опросы после занятия — отложены (схема в БД есть, код не пишется).

## Архитектура

```
┌──────────────┐   polling    ┌─────────────────────────────────────┐
│ Telegram     │ ───────────▶ │  aiogram 3 + aiogram-dialog         │
│ препод+учен  │ ◀── reply ── │  handlers/* (по фичам)              │
└──────────────┘              │  dialogs/* (wizard'ы: NewGroup,     │
                              │  EditGroup, Broadcast, …)           │
                  ┌───────────┴───────────────────────┼─────────────┘
                  ▼                                   ▼
          ┌──────────────┐                  ┌──────────────┐
          │ APScheduler  │                  │  SQLAlchemy  │
          │ tick / 15мин │                  │   (SQLite)   │
          └──────────────┘                  └──────────────┘
```

Бот и scheduler — в одном процессе ([app/main.py](app/main.py)). Бизнес-логика в [app/services/](app/services/) переиспользуется хэндлерами и scheduler'ом. Все wizard'ы и multi-step edit-flow — на [aiogram-dialog](https://github.com/Tishka17/aiogram_dialog), короткие message-handler'ы и колбэки — на чистом aiogram FSM.

**Модель данных:** `School` — top-level контейнер (ростер, площадки, группы) с членством через `SchoolMember(role)`. `Admin` — препод; здесь же его **личные** настройки автодобора (порог, время разбора, добор остатка, `recruit_mode`) и `support_code` для ссылки-приглашения саппорта. `Person` — человек в школе (имя, пол, счётчик помощи, `last_reactivation_at` для throttle реактивации). `Membership` — person↔group. `SupportPoolEntry(admin_id, person_id, level)` — **личный пул** каждого препода. `GroupAdmin` — ответственные за группу (маршрутизация уведомлений + «Мои группы»); `Group.recruit_lead_admin_id` — куратор добора (его пул/настройки/время). `Survey`/`Response` — опрос и ответы. `SupportCall`/`SupportClaim` — автодобор (с отметкой явки; `picker_chat_id/message_id` — ссылка на recruit-сообщение для живого баланс-бара). `LessonCancellation` — отмена занятия.

## Требования

- Python 3.12+
- Telegram-бот-токен от [@BotFather](https://t.me/BotFather)

База данных — SQLite, отдельный сервер не нужен; файл создаётся автоматически.

## Запуск

```powershell
# 1. Окружение и зависимости
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# 2. Настроить .env
copy .env.example .env
# вписать BOT_TOKEN от @BotFather и свой DEVELOPER_ID (Telegram user_id)

# 3. Запустить
python -m app.main
```

SQLite-файл (`dance.sqlite3`) создаётся при первом старте. Логи пишутся в [logs/dance.log](logs/) (rotating, 5 MB × 5 backups).

Проверка с двух Telegram-аккаунтов:
1. Препод: `/start` → `/newgroup` → пройти мастер. Группа создана — есть ссылка и QR-код.
2. Ученик (второй аккаунт): перейти по ссылке → ответить на вопросы про имя и пол.
3. Препод: `/groups` → группа → «Ученики» — ученик в списке; преподу пришло уведомление о записи.
4. Опрос: в `/newgroup` задай время занятия в пределах `DEFAULT_LEAD_HOURS` часов — бот в течение 15 минут разошлёт опрос. Ответь кнопкой, проверь `/today`.

## Roadmap

- **Пилот** — обкатать автосбор саппортов на реальной школе.
- **Автодобор** — модель добора персонализирована по преподу: личные пул/настройки, куратор (lead) на группу, ссылка-приглашение саппорта, двухуровневый picker (свой пул + пул коллег), **4 настраиваемых режима** (curated/open_race/auto_top/escalate) и живой баланс-бар. Тайминг/явка/нуджи закрыты ранее. Открыто только продуктовое: баланс чисто по полу, а не по танц-роли.
- **Доработки по пилоту** — фора личного пула по времени; возможно per-group настройки добора.
- **Рост** — уровень над школой (сеть/франшиза) и role-based баланс, когда появится спрос.

## Решения дизайна

- **SQLite, не Postgres.** Утилите не нужна инфраструктура — один файл.
- **Управление в боте, без веб-панели.** Преподаватель в телефоне.
- **Polling, не webhook.** Не нужен публичный URL.
- **Бот в личке, не в групповом чате.** Автосбор саппортов невозможен на нативных опросах Telegram — нужен поимённый ростер с ролями и личные сообщения подмножеству людей. Это и есть то, что отличает бота от ручной переклички.
- **Один `Person`, а не отдельные «ученики» и «саппорты».** Человек может быть и тем и другим одновременно — это флаги, а не разные сущности.
- **Не дублирует школьную CRM.** Бот знает людей только чтобы слать опрос и собирать саппортов, он не «система записи».
- **Единый визуальный язык «Pulse» ([app/bot/ui.py](app/bot/ui.py)).** Все экраны собираются через один модуль: словарь эмодзи (единый источник правды), русская плюрализация (`plural`), анатомия карточки (`card`), прогресс-бар (`bar`, одна реализация), гендерный баланс (`balance_bars`), единый ряд «назад» (`back_row`). Опрос показывает «кто идёт» поимённо с разбивкой 🕺/💃. Клавиатуры заточены под телефон: длинные действия — на всю ширину, настройки автодобора — самоописательные ряды, callback'и ≤ 64 байт.
