# Dance Pulse

Telegram-бот для танцевальных школ. Делает две вещи, которых нет в коробочных CRM:

1. **Опрос посещаемости** — перед каждым занятием спрашивает учеников «придёшь?» и даёт преподавателю готовую сводку.
2. **Автосбор саппортов** (киллер-фича) — ловит гендерный перекос в парах лид/фолловер и сам добирает помощников из пула.

Это **не CRM**. Учёт абонементов, платежей, расписания залов — у школ для этого уже есть коробочные продукты (AppEvent, Impulse CRM и т.п.). Бот сознательно делает только то, чего эти CRM не делают.

## Что работает

**Преподаватель** — команды `/start`, `/newgroup`, `/groups`, `/today`, `/stats`, `/pool`, `/help`.

- **Создание группы** — мастер: название → дни недели → время. Бот выдаёт ссылку-приглашение и QR-код.
- **Карточка группы** (`/groups`) — список учеников, ссылка, QR-код, удаление.
- **Опросы посещаемости** — за `lead_hours` до занятия бот рассылает ученикам «придёшь?» с кнопками да/нет. `/today` — сводка по ближайшим занятиям; на середине окна преподу уходит авто-сводка.
- **`/stats`** — посещаемость по группам за последние занятия.

**Ученик** — никаких команд, всё кнопками:

- **Онбординг** — переходит по QR-коду или ссылке → бот спрашивает имя (кнопкой с Telegram-именем или вводом) и пол → запись в группу, преподу уведомление.
- Отвечает на опрос одной кнопкой. Может вступить в пул саппортов кнопкой «🆘 иногда выручать».

**Автосбор саппортов:**

- На отсечке (≈6 ч до занятия) бот считает баланс парней/девушек среди ответивших «приду».
- Если перекос ≥ порога — спрашивает преподавателя «добрать саппортов?».
- По подтверждению рассылает пулам: личный пул преподавателя первым, затем общий (если scope = «свой + общий»).
- Первый откликнувшийся занимает место; преподу — живые уведомления; у саппорта растёт счётчик «помог N раз».
- `/pool` — преподаватель ведёт личный пул и переключает scope.

Фидбек-опросы после занятия — отложены (потребность не подтверждена; схема в БД есть, код не пишется).

## Архитектура

```
┌──────────────┐   polling    ┌──────────────────────┐
│ Telegram     │ ───────────▶ │  aiogram 3           │
│ препод+учен  │ ◀── reply ── │  handlers            │
└──────────────┘              │ teacher/student/     │
                              │ survey/recruit       │
                  ┌───────────┴──────────┼───────────┐
                  ▼                      ▼            │
          ┌──────────────┐      ┌──────────────┐      │
          │ APScheduler  │      │  SQLAlchemy  │◀─────┘
          │ tick / 15мин │      │   (SQLite)   │
          └──────────────┘      └──────────────┘
```

Бот и scheduler — в одном процессе ([app/main.py](app/main.py)). Бизнес-логика в [app/services/](app/services/) переиспользуется хэндлерами и scheduler'ом.

**Модель данных:** `Person` — человек в аудитории преподавателя (имя, пол, флаги пулов, счётчик помощи). `Membership` — связь человека с группой (многие-ко-многим: один человек может быть в нескольких группах). `Survey`/`Response` — опрос на занятие и ответы. `SupportCall`/`SupportClaim` — заявка на саппортов и отклики.

## Требования

- Python 3.12+
- Telegram-бот-токен от [@BotFather](https://t.me/BotFather)

База данных — SQLite, отдельный сервер не нужен; файл создаётся автоматически.

## Запуск

```powershell
# 1. Окружение и зависимости
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# 2. Настроить .env
copy .env.example .env
# вписать BOT_TOKEN от @BotFather

# 3. Запустить
python -m app.main
```

SQLite-файл (`dance.sqlite3`) создаётся при первом старте.

Проверка с двух Telegram-аккаунтов:
1. Препод: `/start` → `/newgroup` → пройти мастер. Группа создана — есть ссылка и QR-код.
2. Ученик (второй аккаунт): перейти по ссылке → ответить на вопросы про имя и пол.
3. Препод: `/groups` → группа → «Ученики» — ученик в списке; преподу пришло уведомление о записи.
4. Опрос: в `/newgroup` задай время занятия в пределах `DEFAULT_LEAD_HOURS` часов — бот в течение 15 минут разошлёт опрос. Ответь кнопкой, проверь `/today`.

## Roadmap

- **Пилот** — обкатать автосбор саппортов на реальной школе.
- **Доработки по пилоту** — фора личного пула по времени (сейчас рассылка одним проходом), экспорт статистики, учёт надёжности саппортов.
- **Рост** — уровень «школа» над преподавателем, когда появится спрос (см. план).

## Решения дизайна

- **SQLite, не Postgres.** Утилите не нужна инфраструктура — один файл.
- **Управление в боте, без веб-панели.** Преподаватель в телефоне.
- **Polling, не webhook.** Не нужен публичный URL.
- **Бот в личке, не в групповом чате.** Автосбор саппортов невозможен на нативных опросах Telegram — нужен поимённый ростер с ролями и личные сообщения подмножеству людей. Это и есть то, что отличает бота от ручной переклички.
- **Один `Person`, а не отдельные «ученики» и «саппорты».** Человек может быть и тем и другим одновременно — это флаги, а не разные сущности.
- **Не дублирует школьную CRM.** Бот знает людей только чтобы слать опрос и собирать саппортов, он не «система записи».
